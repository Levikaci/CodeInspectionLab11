# Лабораторная работа № 11 — исходный проект для инспекции кода

**МДК.02.01 «Технология разработки программного обеспечения»**, 2 академических часа.

## Исходная ситуация

Перед вами небольшой консольный модуль обработки заказов на C#/.NET 9. Он рассчитывает стоимость с учётом категории клиента, выводит заказы в консоль и сохраняет их в CSV. Код передан на инспекцию перед дальнейшим сопровождением. Его функциональные требования изменять нельзя.

## Функциональные требования, которые необходимо сохранить

1. Добавление заказа с идентификатором, именем клиента, категорией и позициями.
2. Сумма позиции = цена × количество; итог заказа = сумма позиций.
3. Категория `vip` даёт скидку 10%, `staff` — 15%, `regular` — без скидки.
4. Если сумма **после процентной скидки** строго больше 10 000, вычитаются 300.
5. Программа выводит заказы и их стоимость, суммарную стоимость заказов и текстовую сводку.
6. Программа записывает в `orders.csv` строки `Id;Customer;Total` с десятичной точкой, используя разделитель `;` (без заголовка).
7. Для отсутствующего заказа метод `GetTotal` исходно возвращает `-1`. Изменение этого контракта требует согласования, а не молчаливой правки.

Ожидаемые итоги для двух предустановленных заказов: **5 850** и **11 700**; общая сумма **17 550**. После запуска должен появиться файл `orders.csv` с двумя строками.

## Порядок выполнения

1. Ознакомьтесь с `Program.cs`, `src/OrderProcessor.cs` и `.editorconfig`.
2. Зафиксируйте исходный запуск и результаты: `dotnet --version`, `dotnet restore`, `dotnet build`, `dotnet run`.
3. Запустите анализаторы командой `dotnet format analyzers --verify-no-changes --verbosity diagnostic` (допускается наличие замечаний); при необходимости выполните также `dotnet format style --verify-no-changes --verbosity diagnostic`.
4. Проведите инспекцию вручную по чек-листу лабораторной: имена, ответственность методов, дублирование, обработка исключений, `Async`, публичные контракты, секреты, форматирование.
5. Запишите не менее **8 замечаний** в таблицу с указанием файла/строки, проблемы, правила или риска и категории (`обязательное исправление`, `рекомендация`, `вопрос автору`). Если фактических нарушений менее восьми, обоснуйте проверенные пункты.
6. Исправьте **минимум 3 замечания** без изменения описанных выше функциональных требований. Приведите фрагменты **до/после** и обоснование.
7. Повторно выполните сборку, запуск и проверку `orders.csv`; сравните результат с исходным.

**Важно:** замечание должно быть технически обосновано. Не нужно исправлять всё подряд или изменять логику программы «для красоты». Не используйте `dotnet format` для автоматического исправления до фиксации исходных замечаний. Данные для тестов демонстрационные и не являются секретами.
